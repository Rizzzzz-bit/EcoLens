PROBLEM 1 — RESEED DID NOT USE THE UPDATED SEED.PY (CRITICAL)
--------------------------------------------------------------
The 150 tickets currently in the database still have the old Lucknow coordinates.

Sample bad coordinates:
  ticket id=151  lat=26.84769  lng=80.94934   (Lucknow — outside CSJMU)
  ticket id=152  lat=26.85008  lng=80.94477   (Lucknow — outside CSJMU)
  ticket id=153  lat=26.85024  lng=80.94688   (Lucknow — outside CSJMU)

Ticket IDs start at 151 (not 1), which means the original 150 rows were cleared,
but the new 150 rows were inserted by the OLD seed.py baked into the backend image.
The backend container was never rebuilt after seed.py was updated, so it ran the
stale version with the 26.847x / 80.948x department anchors.

Fix: rebuild the backend Docker image, then clear and reseed.

Only admin sees all campus-wide tickets. Every other role sees a private subset.
CampusMap calls getTickets({ limit: 200 }), which hits this scoped endpoint,
so non-admin users never receive the full set of markers to render.


WHY THE HEATMAP COUNTER SHOWS A NUMBER BUT MARKERS ARE MISSING
--------------------------------------------------------------
GET /tickets/heatmap  — no role filter, returns all 99 non-resolved tickets.
                        This is why the top-right counter shows "99 open issues".

GET /tickets          — role-scoped, returns only the current user's subset.
                        CampusMap uses this for the coloured CircleMarker layer.

Both endpoints currently return off-screen coordinates (Problem 1), but even
after coordinates are fixed, the marker layer will only show the user's private
subset — not the full campus picture — until Problem 2 is also resolved.


RECOMMENDED FIX FOR PROBLEM 2 — NEW READ-ONLY MAP ENDPOINT
-----------------------------------------------------------
Add a dedicated endpoint:

    GET /tickets/map-points

Behaviour:
  - No role filter — campus-wide, same access model as /tickets/heatmap
  - Returns only: { id, lat, lng, category, status }
  - No reporter_id, no action_recommendation, no user PII
  - Filters out resolved tickets
  - Requires authentication (get_current_user is sufficient)
  - Does NOT modify or touch the existing /tickets endpoint

Update CampusMap.tsx to call getMapPoints() for the coloured marker layer
instead of getTickets({ limit: 200 }). The /tickets endpoint continues
serving its privacy-scoped role for MyTickets, DeptPortal, etc., unchanged.

This is the same pattern already used for /tickets/heatmap — map data is
already treated as a separate concern from the tickets list.
